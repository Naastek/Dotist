# 2026-11-01 气泡动画测量与优化

本次只调整原生 `DotistApp.swift` 的两处曲线，保留同工作区的其他原生改造。没有提交、推送或替换本机安装版；统一安装由交付聊天负责。

## 已实现

- 主窗口收放改为 AppKit 标准 `easeInEaseOut`，总时长仍为收起 0.28 秒、展开 0.34 秒。原 `(0.22, 1, 0.36, 1)` 曲线把较多位移放在最初几个更新中。
- 圆球与横条改为 SwiftUI `easeInOut(duration: 0.26)`，替代 response 0.34、dampingFraction 0.9 的弹簧。保留 220ms 离开防抖、同向文字、圆心锚点及完成回调。
- 目标尺寸、窗口位置、拖动、右键菜单、任务与数据语义不在本次改动范围内。

## 方法与证据边界

最终 A/B 使用同一份 macOS 26+ Swift / GRDB / MCP 源码快照，只有两处曲线不同。两包均为 release、相同隔离数据库与设置、364×620pt 主面板、浅色中文和 2× 缩放；显示器报告最高 120Hz。每包连续六轮，每轮包含主窗收起、横条展开、横条收回、主窗展开，共 24 个阶段。

采样记录动作前几何、每次 `CADisplayLink` 回调的二维窗口与玻璃几何、`timestamp`、`targetTimestamp` 和回调实际执行时间。测量窗口通过 `open -g --background` 启动，使用普通窗口层级和鼠标穿透，不主动激活或抢焦点。驱动调用实际的 `toggleBubble` / `setHover`；测量副本仅关闭闲置轮询中的自动鼠标离开分支，以免真实指针打断合成动作。物理悬停另用 XCTest 验收。

两份环境记录均未采到重叠的 `xcodebuild test`。普通桌面应用和 QA 预览可能仍在运行，因此不是完全隔离的图形基准。

这些数据是主线程回调及几何更新，不是光学呈现 FPS。单次更新的宽度取整、同一帧内多次布局都不能计为掉帧。原始样本中 49→48pt 的 67ms 宽度事件间隔期间，显示回调仍在继续。

每轮最大采样跳变包含“动作发出至首次回调”，其余为相邻回调；按该次形变的总二维尺寸变化归一化。几何耗时使用 0.1%→99.9% 阈值，不等于 `.removed` 完成或交互解锁。目标来自独立约束：收起 48×48、展开恢复初始主窗、横条与已经到位的物理窗口等宽；末五次采样均需稳定在目标范围。

## 最终结果

下表为每轮最大采样形变跳变的中位值，数值越小表示最大采样跳变更小；单独这个峰值指标不足以证明整个过程的均匀程度。

| 方向 | 原曲线 | 优化后 |
| --- | ---: | ---: |
| 主窗收起 | 25.513% | 10.100% |
| 主窗展开 | 25.855% | 8.353% |
| 横条展开 | 7.341% | 5.857% |
| 横条收回 | 7.275% | 5.796% |

| 几何 0.1%→99.9% 耗时中位值 | 原曲线 | 优化后 |
| --- | ---: | ---: |
| 主窗收起 | 262.767ms | 259.800ms |
| 主窗展开 | 245.815ms | 309.432ms |
| 横条展开 | 341.669ms | 249.999ms |
| 横条收回 | 341.666ms | 253.656ms |

主窗展开的可见变化延长约 64ms，是将早段位移摊开到原有 340ms 总时长的取舍；不是四个方向都更快。横条约减少 90ms 可见形变尾段，220ms 离开防抖未计入表内形变时间。

回调间隔中位仍约 8.33ms。活动期 P95：主窗收起 16.675→20.900ms，展开 21.115→19.536ms，横条展开 8.363→8.363ms，收回 8.363→8.360ms。优化后最长活动回调间隔为 39.602ms。曲线调整改善了几何节奏，不能据此宣称消除所有长回调、零卡顿或稳定 120FPS。样本仅一台机器、每包六轮，没有统计性提速结论。
